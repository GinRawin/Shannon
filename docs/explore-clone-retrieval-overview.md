# Explore 克隆检索方法简介

## 定位

Explore 用**确定性代码克隆检索**（`normalized_token_clone_v1`）替代旧的「模型生成正则 + ripgrep 模板搜索」。

- 不调用模型，纯本地计算，可复现、零成本；
- 只做**检索**：命中只表示"代码长得像"，是否为漏洞由后续按类扩展分析判断；
- 目标为 Type-2（改名 / 换字面量）与 Type-3（少量语句增删）克隆，不做 Type-4 语义克隆。

## 方法流程

1. **取种子**：取已验证且状态为"已利用"的漏洞代码位置（文件 + 行号），去重并校验路径在仓库内。
2. **选锚点**：在记录行挑代表性 token（优先调用形状标识符，其次最稀有标识符）；该行无 token 时上下各扩 3 行。
3. **截窗口**：以锚点为中心取连续 token 窗口。
4. **归一化**：标识符、字符串、数字、正则统一抹平；关键字、运算符、标点保留。改名与换字面量后序列不变，语句增删只打断跨过的 n-gram。
5. **建索引**：整仓切滑窗，抽取 5-gram 哈希汇成共享倒排索引（只索引本次用到的语言）。
6. **打分初筛**：得分 = 命中种子 n-gram 占种子总量的比例；过阈后折叠同文件重叠窗。
7. **对齐定位**：与种子做序列对齐，要求锚点出现且对齐比例达标；命中行取自候选侧锚点的真实语句行，对不齐则丢弃。
8. **去重限额**：排除自匹配、重叠窗、重复三元组；种子间交错输出后按上限截断（截断会标记，不静默丢候选）。

## 参数取值

| 类别 | 参数 |
|---|---|
| 索引/打分 | n-gram 宽度 `5`；相似度阈值 `0.55`；最少共享 n-gram `8` |
| 种子窗口 | 目标 `80` token（`40–120`）；低于 `25` 跳过；无 token 时扩宽 `3` 行 |
| 候选窗口 | 长度 `50–150` token，步进 `10`；每种子精细对齐区域上限 `20` |
| 对齐 | 种子对齐比例下限 `0.5` |
| 输出预算 | 种子 `30`、每种子命中 `10`、全局命中 `100` |
| 扫描上限 | 文件 `5000`、单文件 `1 MB`、总 token `80 万`、总窗口 `12 万` |
| 摘录 | 每条命中摘录上限 `800` 字符 |

## 产物

- 检索结果：命中清单（命中文件/行、候选起止行、分数、摘录）；
- 种子清单；覆盖率报告（验证/可用/已索引/跳过/命中/截断 + 每种子状态与跳过原因）；
- 人读摘要文档。旧的模板类产物会被删除。

## 下游使用

- **精确行准入**：扩展分析提交的危险点位置必须覆盖某条命中行，仅文件名相同不算；
- 相似度只是准入门槛，**不是漏洞证据**，必须回到完整路径、数据流、守卫与鉴权判断；
- 安全变体（同操作但加了归属/角色校验）必须拒绝；
- 命中可"富集"已有发现，或以本类新编号提交为独立新候选，再走利用与记录流程。

## 范围与局限

- 语言：仅 JS/TS 家族与 Java；其他语言跳过，不做跨语言匹配；
- 能力：纯词法/结构，无 AST、无数据流/污点、无语义克隆；分数是检索信号而非判定；
- 覆盖：大仓库会被上限截断，需检查 `truncated` 与覆盖率报告。
